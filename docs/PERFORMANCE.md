# BlenderUIDemo 性能分析与诊断设计

## 1. 问题现象

旧版本在部分 Windows 设备上会出现明显高于预期的 CPU 占用。对于系统信息面板而言，界面数据变化速度较慢，持续以显示器刷新率甚至无限帧率重建完整 UI 并不划算。

CPU 占用不能只看某一次采集函数耗时。该应用的成本由以下部分共同组成：

```text
事件处理
+ 系统采集
+ Dear ImGui 布局与 DrawList 生成
+ OpenGL 提交
+ 缓冲交换与 VSync 等待
+ 帧率控制
```

新版在界面中分别记录这些模块的最近耗时和指数平滑平均耗时。

## 2. 已确认的主要原因

### 2.1 持续逐帧重建 UI

Dear ImGui 属于即时模式 UI。每一帧都需要重新执行界面声明、布局计算和 DrawList 构建。旧版本即使数据没有变化，也会持续完成整套工作。

处理方式：默认限制为 30 FPS。系统仪表盘不需要游戏级 120/144 FPS。

### 2.2 VSync 可能没有真正生效

调用 `SDL_GL_SetSwapInterval(1)` 不代表驱动一定接受。旧版本没有检查返回值。如果 VSync 被拒绝，循环可能以数百或数千 FPS 运行。

处理方式：记录 VSync 是否启用，并始终使用软件帧率上限作为兜底。

### 2.3 快速指标与慢速清单混在一起

CPU、内存和应用自身指标很轻量，但磁盘枚举、进程快照和部分网络信息更加昂贵。旧版本每 500ms 都重新读取全部磁盘。

处理方式：

- 快速采集：默认 1000ms，包含 CPU、内存、应用自身和网络计数器。
- 慢速采集：默认 5000ms，包含磁盘和进程清单。
- 慢速结果缓存在 `SystemMonitor` 内部。

### 2.4 图表产生逐帧分配和复制

旧版本每帧把 `deque<float>` 复制为新的 `vector<float>`，再传给 ImGui 图表。

处理方式：使用 120 个元素的固定数组作为环形缓冲区，直接传入图表，不进行逐帧堆分配。

### 2.5 后台窗口没有降频

不可见或失焦的窗口仍然以正常速率绘制没有实际价值。

处理方式：

- 失焦：10 FPS。
- 最小化：每轮休眠 120ms，跳过 UI 构建与绘制。

## 3. Diagnostics 页面

Diagnostics 工作区包括：

- 应用自身 CPU、内存、FPS 和帧时间。
- Platform & Events：SDL 事件处理。
- System Telemetry：系统采集。
- UI Composition：Dear ImGui 布局和 DrawList 构建。
- OpenGL Renderer：图形提交。
- Buffer Swap：VSync 和前后缓冲交换。
- Frame Throttle：软件限帧等待。
- CPU 高占用原因的动态判断。
- CPU/内存、网络、磁盘和进程采集耗时拆分。

诊断文字来自当前实际状态，例如：

- VSync 未启用但软件限帧正在兜底。
- 用户选择了 60 FPS。
- Dear ImGui Demo 窗口已开启。
- UI 组合或 OpenGL 绘制超过模块预算。
- 进程清单扫描成为慢采集主耗时。

## 4. 指标解释

### 应用 CPU

Windows `GetProcessTimes` 返回进程累计内核态和用户态 CPU 时间。新版根据两次采样差值计算，并除以逻辑处理器数量，使结果接近任务管理器对整机 CPU 容量的表示方式。

### Buffer Swap

若 VSync 生效，Buffer Swap 可能显示十几毫秒。这通常是等待显示器刷新，而不是 CPU 正在执行十几毫秒的计算，因此不能直接将其视为性能故障。

### Frame Throttle

该模块耗时越高，通常说明程序越多时间处于休眠状态，反而代表 CPU 主动让出了执行时间。

### Collector Total

Collector Total 只在采样帧发生。慢速采集执行时会包含磁盘和进程快照，单次较高并不代表持续高 CPU，应该结合采样频率判断。

## 5. 推荐默认值

| 设置 | 默认值 | 说明 |
|---|---:|---|
| 前台 FPS | 30 | 兼顾流畅度和功耗 |
| 后台 FPS | 10 | 窗口失焦时自动启用 |
| 快速采集 | 1000ms | CPU、内存、网络、自身指标 |
| 慢速采集 | 5000ms | 磁盘与进程清单 |
| 历史样本 | 120 | 约两分钟快速采样历史 |

低功耗设备可改为 15 FPS 和 2000ms 快速采集；需要观察快速动画时才建议使用 60 FPS。

## 6. 后续可扩展方向

- 使用 ETW 对线程、进程 CPU、磁盘和网络进行更精确归因。
- 使用 DXGI/D3DKMT 获取实时 GPU 引擎与显存使用率。
- 将慢速采集移动到固定 Worker，并用双缓冲快照交给 UI 线程。
- 增加帧时间百分位数与卡顿事件记录。
- 增加性能策略持久化与低功耗模式。
